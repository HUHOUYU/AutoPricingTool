# 批次日志与数据统计

本文档描述当前代码中的批次追溯和统计口径。事实来源主要是：

- `src/main/task-history-store.ts`
- `src/shared/task-history.ts`
- `src/renderer/src/components/log-center-page.tsx`
- `src/renderer/src/components/analytics-page.tsx`

## 1. 批次定义

一次导入定义一个业务批次。导入成功后，文件处理页先建立前端草稿；第一次实际提交
`price-check-run` 时，主进程才创建不可变批次 ID 并写入历史。单纯导入文件、分析
候选 Sheet 或修改字段映射不会创建历史记录。

同一批次内的自动处理、逐个人工确认和重新处理都携带相同批次 ID。文件结果按路径
保留最新状态，因此重试不会重复累计文件数、总行数或异常数。事件时间线会标记本次
执行属于“自动处理”“人工确认处理”或“重新处理”。

批次还包含可编辑的名称和备注：

- 默认名称按文件夹名、单文件名或“首文件等 N 个文件”生成。
- 开始处理前可在文件列表标题区修改名称。
- 历史批次可在日志中心继续修改名称和备注；名称清空后恢复自动名称。
- 名称和备注用于识别与筛选，不参与批次关联；真正的数据关联始终使用批次 ID。
- 首次核价时会在所选输出根目录下创建以批次名称命名的结果文件夹；同一批次的
  自动处理、人工确认和重试复用该文件夹。批次重名时追加序号，Windows 路径非法
  字符会替换为安全字符。
- 批次处理完成后修改名称，会同步重命名结果文件夹及历史中的结果文件路径；
  批次正在写入文件时禁止改名。
- 完成批次点击“处理下一批”后回到文件导入页，不会移动原始文件，也不会自动
  弹出文件选择器。
- 主动“结束并下一批”时，所有没有有效核价结果的文件会复制到批次结果目录下的
  `未处理` 文件夹；原始输入文件保持不变。归档全部成功后才结束并清空当前批次，
  失败时保留当前文件列表和编辑状态。

批次状态包括：

| 状态 | 含义 |
|---|---|
| `running` | 核价处理仍在运行 |
| `awaiting_confirmation` | 本轮处理结束，但业务批次仍有待确认或未处理文件 |
| `completed` | 所有文件处理完成且没有文件级失败 |
| `failed` | 批次结束，但至少一个文件处理失败 |
| `stopped` | 用户主动停止 |
| `interrupted` | 应用退出后发现上次批次没有正常结束 |

全部文件完成时批次自动结束；存在待确认文件时保持待处理。用户选择“结束并下一批”
时，未处理文件标记为未完成，批次进入 `stopped`。暂停、继续、停止、文件开始、
文件完成、文件失败和批次结束都会写入事件时间线。

## 2. 保存位置与兼容性

开发态数据位于项目 `runtime/`，打包后位于应用可写数据目录：

```text
runtime/
  task-history.jsonl       # 批次汇总索引
  task-details/
    <batch-id>.jsonl       # 文件结果快照与事件时间线
  logs/app.log             # 技术支持日志，不作为日志中心数据源
```

- 汇总索引保留最近 365 天、最多 1,000 个批次。
- 清理汇总记录时同步删除对应详情文件。
- JSONL 最后一行被异常中断时，读取会忽略该行并保留此前有效记录。
- 旧版本汇总记录仍可读取；没有详情文件时，日志中心显示“仅有汇总”，不会补造文件明细。

## 3. 详情内容与隐私边界

每个文件保存状态、处理时间、耗时、总行数、匹配行数、异常行数、覆盖率、
输出路径和文件级失败原因。

异常按稳定分类汇总：

- 数量计算
- 国家路由
- SKU
- 数量档位
- 价格不可用或重复
- 文件处理失败
- 其他

完整异常数量会进入统计。每个文件只保留有限问题样例，样例字段为源行、国家、
SKU、数量和原因。不会持久化收件人姓名、电话、邮箱或地址，也不会保存工作簿快照。

## 4. 日志中心

日志中心是独立导航页面，不再使用覆盖工作区的右侧日志抽屉。

- 默认查询最近 7 天，支持日期、状态以及批次名称、备注、文件名关键词筛选。
- 左侧为批次列表，右侧为批次指标、文件结果、异常分类和事件时间线。
- 详情中可修改批次名称和备注；修改不会改变批次 ID 或历史文件结果。
- “结果目录”打开当前批次文件夹；文件结果表右侧的打开按钮直接打开该文件保存的
  绝对结果路径。历史记录不根据文件名临时推测路径。
- 已完成文件的打开按钮指向核价结果；未完成文件指向批次 `未处理` 目录中的归档
  副本。路径缺失或文件不存在时直接提示错误，不回退打开原始输入文件。
- 点击文件后，异常和事件只显示该文件；再次点击恢复整个批次。
- 当前运行批次自动定时刷新。
- 窄窗口切换为批次列表和详情两个单栏视图。
- 支持打开结果目录、导出当前批次 JSON、导出筛选批次 CSV。

## 5. 数据统计口径

数据统计默认查询最近 30 天，可切换 30 天、60 天、90 天或自定义日期，并可按
批次名称、备注或文件名筛选。指标、图表和批次明细使用同一筛选结果。

| 指标 | 口径 |
|---|---|
| 处理批次 | 所选时间范围内开始的批次数 |
| 处理文件 | 批次 `totalFiles` 之和 |
| 处理总行数 | 批次 `totalRows` 之和 |
| 匹配率 | `matchedRows ÷ totalRows`；分母为 0 时显示空值 |
| 异常行 | 批次 `exceptionRows` 之和 |
| 平均批次耗时 | 仅统计已经结束且具有耗时的批次 |

趋势、状态分布、异常原因和底部批次表均来自同一个历史存储聚合，必须与指标卡
对账一致。批次明细显示可读批次名称；点击批次表行会打开日志中心并定位相同批次。

工作台只展示今日摘要和快捷入口；数据统计负责跨批次趋势；日志中心负责具体批次追溯。
