# 配置说明（extract_rules.json）

工具通过 `configPath` 读取统一 JSON 配置。默认模板在 `resources/defaults/extract_rules.json`；开发/本机常用 `config/extract_rules.json`（可含本机路径，**不宜盲目提交**）。

配置为 **纯 JSON，无注释**。正则在加载时编译，非法表达式会报错。

下文区分：

- **生效**：Rust `config.rs` / 主进程 / 渲染进程实际读取  
- **JSON 残留**：可能出现在文件中，但当前结构体 **未反序列化使用**

---

## 1. 结构总览

```json
{
  "sheet_rules": {},
  "sheet_selection": {},
  "performance": {},
  "automation": {},
  "pricing": {},
  "runtime": {},
  "fields": {},
  "pricing_fields": {
    "order": {},
    "pricing": {}
  },
  "output": {},
  "filename_rules": {}
}
```

核价主路径主要使用：`sheet_rules`、`performance`、`automation`、`pricing`、`pricing_fields`、`output`（部分）、`runtime`（主进程路径记忆）。

---

## 2. pricing — 核价规则（生效）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `country_identity` | `string[]` | `["iso2","english","chinese"]` | 订单侧参与国家解析的身份：`iso2` / `english` / `chinese`。未列出的字段读入时当作空。 |
| `single_shipment_price_marker_aliases` | `string[]` | 单独发货价格/价/报价 | 核价表中标记「单独发货价区」起始的表头别名；规范化后 **整格相等** 才算命中。标记行 **之后** 的行进入单独发货子索引。 |
| `single_shipment_matching_enabled` | `boolean` | `false` | 是否启用单独发货价格匹配；关闭时全部使用通用价格。 |
| `single_shipment_match_fields` | `string[]` | `["recipient_name","phone","postal_code"]` | 联合判断字段。启用时至少选择两个不同字段；支持 `recipient_name`、`phone`、`postal_code`、`address`、`email`。 |

### 2.1 JSON 中常见但当前未接入 PricingRules 的键

下列键若出现在 `pricing` 对象中，**当前 Rust 不会使用**（查找为精确数量档位、无物流匹配）：

| 键 | 说明 |
|---|---|
| `match_by_shipping_method` | **已删除**；勿再依赖 |
| `sku_qty_pair_selection` | 未映射到 `PricingRules` |
| `quantity_policy`（如 `nearest`） | 未实现就近档；`lookup` 要求精确数量 |
| `multiply_quantity_by_price` | 未映射 |
| `zero_price_is_valid` | 未映射 |
| `unavailable_price_tokens` | 未映射 |
| `output_sheets` | 未映射到 `PricingRules` |

以代码 `PricingRules` 为准，勿按 JSON 残留推断行为。

## 3. automation — 自动化试算

| 字段 | 类型 | 代码默认 | 说明 |
|---|---|---|---|
| `auto_run` | bool | `true` | 关闭后即使覆盖率达标也不自动执行 |
| `template_match_priority` | bool | `false` | 为 true 时优先用表头模板套映射 |
| `coverage_threshold` | number | `0.98`（默认函数；仓库 defaults 可能为 `1`） | 试算行数 ≥ `min_trial_rows` 时，覆盖率须 ≥ 该值才 eligible |
| `min_trial_rows` | number | `10`（defaults 可能为 `20`） | 少于此行数时要求覆盖率 100% |
| `candidate_coverage_gap` | number | `0.02` | 候选映射覆盖率差距过小视为歧义 |
| `candidate_score_gap` | number | `12`（defaults 可能为 `5`） | 候选分数差距过小视为歧义 |

覆盖率 = 匹配成功行 / 参与评价的订单行。

## 4. pricing_fields — 列识别规则（生效）

```json
"pricing_fields": {
  "order": { "<field>": { FieldRule } },
  "pricing": { "<field>": { FieldRule } }
}
```

### 4.1 FieldRule

| 字段 | 说明 |
|---|---|
| `header_aliases` | 表头别名，**数组顺序**在同分时影响优先级 |
| `value_patterns` | 样本值正则，提升列分 |
| `negative_patterns` | 样本命中则扣分/排除 |
| `negative_headers` | 表头命中强惩罚 |
| `low_priority_headers` | 表头低优先 |
| `require_empty_header` | 要求空表头 |
| `required` / `pair_with` / `output_header` | 通用字段规则（与提取链路共用结构） |

### 4.2 订单侧常用 field 键

| 键 | 用途 |
|---|---|
| `order_number` | 业务订单号 |
| `country_code` | 二字码 |
| `country_english` | 英文国家 |
| `country_chinese` | 中文国家 |
| `sku` / `quantity` / `product_name` / `price` | SKU、数量、品名、原价 |

**无** `shipping_method` 订单字段规则。

### 4.3 核价侧常用 field 键

| 键 | 用途 |
|---|---|
| `sku` | 核价 SKU |
| `country` | 核价国家（整格） |
| `fixed_price` | 固定/单列价格表头识别（与数量阶梯档位识别配合） |

数量档位列多由表头数字阶梯 + 价格样本推断，见 `pricing.rs` 候选推断逻辑。

## 5. sheet_rules

| 字段 | 默认（代码） | 说明 |
|---|---|---|
| `header_scan_rows` | 20 | 向前扫描表头行数（核价侧另有常量上限） |
| `data_sample_rows` | 30 | 表头下样本行数 |
| `sample_column_scan_limit` | 130 | 横向扫描列上限 |
| `empty_gap_limit` | 15 | 连续空行停止策略相关 |
| `preferred_sheet_names` | `[]` | Sheet 名偏好，靠前优先 |

---

## 6. sheet_selection

用于 Sheet/表头评分扣分，例如：

- `reject_header_keywords`
- `sequential_numeric_header_penalty`
- `empty_header_fields_can_boost_sheet` 及财务空表头加分上限/溢出扣分  
- `required_header_fields` 等  

具体默认值见 `config.rs` 与当前 `extract_rules.json`。

---

## 7. performance

| 字段 | 说明 |
|---|---|
| `quick_header_scan_max_mb` | 扫描阶段大文件跳过快速预览阈值 |
| `quick_shared_strings_max_mb` | 扫描 sharedStrings 上限 |
| `processing_workbook_max_mb` | 处理工作簿体积上限 |
| `processing_xml_entry_max_mb` | 单 XML 条目上限 |
| `processing_shared_strings_max_mb` | 处理 sharedStrings 上限 |
| `processing_max_rows` | 单表最大行数，超限失败不静默截断 |
| `processing_workers` | `0` 表示自动；`>0` 为并行上限 |

## 8. runtime（主进程维护）

| 字段 | 说明 |
|---|---|
| `recent_input_dir` / `recent_output_dir` / `recent_config_path` | 最近路径 |
| `archive_standard_files` | 是否归档标准文件（与批处理链路相关） |
| `auto_reveal_manual_result` | 是否自动打开人工结果 |

路径为 **本机状态**，同步远程时注意保留本地值。

## 9. output

Rust `OutputRules` 当前主要使用：

| 字段 | 说明 |
|---|---|
| `max_sku_groups` | SKU 组数量上限相关 |
| `summary_flush_files` / `summary_flush_rows` | 汇总刷新阈值（批处理链路） |

JSON 中其他 flush 字段以实际反序列化结构为准。

---

## 10. 国家与单独发货（配置 + 代码常量）

- 国家目录：`processor-rust/src/country_catalog.rs`（别名表，非 JSON）。  
- 单独发货价区由 `pricing.single_shipment_price_marker_aliases` 标记。
- 单独发货匹配默认关闭；开启后按配置中心勾选的收件信息字段自动定位表头。
- 只有联合字段完整、只对应一个订单号且订单只有一个有效主要 SKU 时使用单独发货价；其余回退通用价格。

---

## 11. 热更新语义

| 操作 | 是否读最新配置 |
|---|---|
| 已启动的 analyze/run 任务 | 否（任务开始时已 load） |
| 下一次 analyze / validate / run | 是 |

改别名或阈值后保存 JSON，再触发分析/试算即可验证。
