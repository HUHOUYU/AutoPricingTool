# 配置说明（extract_rules.json）

工具通过 `configPath` 读取业务规则 JSON。配置文件的生命周期由
`src/main/index.ts` 中的 `ensureWritableConfig`、`resolveActiveConfigPath` 和
`AppSettingsStore` 决定：

- 开发态默认使用 `config/extract_rules.json`。
- 打包默认模板位于 `resources/defaults/extract_rules.json`。
- 打包程序首次启动时，将默认模板复制到
  `%APPDATA%\auto-pricing-tool\config\extract_rules.json`。
- 可写配置已存在时不会被新安装包覆盖；配置中心选择的其他配置文件路径记录在
  `%APPDATA%\auto-pricing-tool\state.json`。

因此，修改仓库默认模板不会自动修改用户机器上已存在的配置。业务规则文件不得
包含本机路径；配置校验发现根节点 `runtime` 会直接报错。

配置为 **纯 JSON，无注释**。正则在加载时编译，非法表达式会报错。

下文区分：

- **生效**：Rust `config.rs` / 主进程 / 渲染进程实际读取  
- **JSON 残留**：可能出现在文件中，但当前结构体 **未反序列化使用**

配置事实来源依次为：`processor-rust/src/config.rs` 的反序列化结构、
`src/main/index.ts` 的主进程校验与应用设置逻辑、最后才是 JSON 示例。

---

## 1. 结构总览

```json
{
  "sheet_rules": {},
  "sheet_selection": {},
  "performance": {},
  "automation": {},
  "pricing": {},
  "fields": {},
  "pricing_fields": {
    "order": {},
    "pricing": {}
  },
  "output": {},
  "filename_rules": {}
}
```

核价主路径主要使用：`sheet_rules`、`performance`、`automation`、`pricing`、
`pricing_fields`、`output`（部分）。

## 2. pricing — 核价规则（生效）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `country_identity` | `string[]` | `["iso2","english","chinese"]` | 订单侧参与国家解析的身份：`iso2` / `english` / `chinese`。未列出的字段读入时当作空。 |
| `single_shipment_price_marker_aliases` | `string[]` | 单独发货价格/价/报价 | 核价表中标记「单独发货价区」起始的表头别名；规范化后 **整格相等** 才算命中。标记行 **之后** 的行进入单独发货子索引。 |
| `single_shipment_matching_enabled` | `boolean` | `false` | 是否启用单独发货价格匹配；关闭时全部使用通用价格。 |
| `single_shipment_match_fields` | `string[]` | `["recipient_name","phone","postal_code"]` | 联合判断字段。启用时至少选择两个不同字段；支持 `recipient_name`、`phone`、`postal_code`、`address`、`email`。 |

`single_shipment_match_fields` 决定启用哪些业务字段；各字段的表头别名分别配置在
`pricing_fields.order.recipient_name`、`phone`、`postal_code`、`address`、`email`。
当前文件分析后，还可以在字段映射的「单独发货判断」中逐项手动改列。`address`
自动识别时可以合并多个地址列，人工改列后使用所选单列；其他字段只取首个命中列。
任一已选字段缺列或缺值、同一订单出现多个联合值、联合值对应多个订单，或订单内
存在多个有效主要 SKU，都会使用通用价格。

### 2.1 已停用配置键

以下旧键已从仓库默认配置和配置中心移除；配置校验发现这些键时会直接提示删除，
避免出现“界面可修改、处理器不读取”的伪配置：

- `match_by_shipping_method`
- `sku_qty_pair_selection`
- `quantity_policy`
- `multiply_quantity_by_price`
- `zero_price_is_valid`
- `unavailable_price_tokens`
- `output_sheets`

当前数量档位必须精确匹配。主要 SKU 数量来源、`+`/`*N` 换算、同订单吸收和
合并都是 `pricing.rs` 中的固定业务规则，没有对应 JSON 开关。

配置中心保存后，若已有导入文件且当前没有正在执行的任务，程序会立即使用新配置
重新分析这些文件。右侧“单独发货判断”状态与联合字段识别结果均由 Rust 返回，
不会在前端复制另一套表头识别规则。

## 3. automation — 自动化试算

| 字段 | 类型 | 代码默认 | 说明 |
|---|---|---|---|
| `auto_run` | bool | `true` | 关闭后即使覆盖率达标也不自动执行 |
| `template_match_priority` | bool | `false` | 为 true 时优先用表头模板套映射 |
| `coverage_threshold` | number | `0.98`（默认函数；仓库 defaults 可能为 `1`） | 试算行数 ≥ `min_trial_rows` 时，覆盖率须 ≥ 该值才 eligible |
| `min_trial_rows` | number | `10`（defaults 可能为 `20`） | 少于此行数时要求覆盖率 100% |
| `candidate_coverage_gap` | number | `0.02` | 候选映射覆盖率差距过小视为歧义 |
| `candidate_score_gap` | number | `12`（defaults 可能为 `5`） | 候选分数差距过小视为歧义 |

覆盖率 = 匹配成功行 / 参与评价的订单行。

## 4. pricing_fields — 列识别规则（生效）

```json
"pricing_fields": {
  "order": { "<field>": { FieldRule } },
  "pricing": { "<field>": { FieldRule } }
}
```

### 4.1 FieldRule

| 字段 | 说明 |
|---|---|
| `header_aliases` | 表头别名，**数组顺序**在同分时影响优先级 |
| `value_patterns` | 样本值正则，提升列分 |
| `negative_patterns` | 样本命中则扣分/排除 |
| `negative_headers` | 表头命中强惩罚 |
| `low_priority_headers` | 表头低优先 |
| `require_empty_header` | 要求空表头 |
| `required` / `pair_with` / `output_header` | 通用字段规则（与提取链路共用结构） |

### 4.2 订单侧常用 field 键

| 键 | 用途 |
|---|---|
| `order_number` | 业务订单号 |
| `country_code` | 二字码 |
| `country_english` | 英文国家 |
| `country_chinese` | 中文国家 |
| `sku` / `quantity` / `product_name` / `price` | SKU、数量、品名、原价 |

**无** `shipping_method` 订单字段规则。

### 4.3 核价侧常用 field 键

| 键 | 用途 |
|---|---|
| `sku` | 核价 SKU |
| `country` | 核价国家（整格） |
| `quantity_one_price` | 没有数字数量档位时，识别仅代表数量 `1` 的单列价格表头 |

数量档位列多由表头数字阶梯 + 价格样本推断，见 `pricing.rs` 候选推断逻辑。
数字档位优先；只有未识别到数字档位时才使用 `quantity_one_price`，且不会把该价格
自动乘以订单数量。旧键 `fixed_price` 仅作为已有本机配置的兼容别名继续读取。

用于 Sheet/表头评分扣分，例如：

- `reject_header_keywords`
- `sequential_numeric_header_penalty`
- `empty_header_fields_can_boost_sheet` 及财务空表头加分上限/溢出扣分  
- `required_header_fields` 等  

具体默认值见 `config.rs` 与当前 `extract_rules.json`。

## 8. 本机应用设置（不属于 extract_rules.json）

主进程把本机设置拆成两个文件，均位于
`%APPDATA%\auto-pricing-tool\`：

| 文件 | 字段 | 职责 |
|---|---|---|
| `preferences.json` | `archiveStandardFiles`、`autoRevealManualResult`、`continuousIssueReviewEnabled`、`overwriteSourceFiles`、`rememberWindowSize` | 用户偏好和界面行为；`overwriteSourceFiles` 开启时，目标文件生成成功后再复制覆盖源文件 |
| `state.json` | `activeBusinessConfigPath`、`recentInputDirectory`、`recentOutputDirectory`、`windowWidth`、`windowHeight` | 路径、窗口尺寸等运行状态 |

配置中心左侧的这些设置独立自动保存，不会改变右侧业务规则 JSON。“连续处理问题
文件”等开关保存成功后立即更新当前界面行为，无需重启。业务规则的修改仍需点击
“保存”，并在下一次分析、试算或核价任务中生效。

新版本不读取旧业务 JSON 中的 `runtime`，也不读取旧的独立运行配置或窗口偏好
文件；需要在配置中心重新选择本机路径和开关。

## 9. output

Rust `OutputRules` 当前主要使用：

| 字段 | 说明 |
|---|---|
| `extracted_sku_group_limit` | 扫描提取及汇总输出中保留的 SKU/数量组上限；不控制自动核价的主要 SKU 规则 |
| `summary_buffer_file_limit` / `summary_buffer_row_limit` | 汇总内存缓冲达到任一阈值后写入工作簿对象；最终任务结束时才强制保存文件 |

旧键 `max_sku_groups`、`summary_flush_files`、`summary_flush_rows` 仅作为已有本机配置的
兼容别名继续读取。`manifest_flush_files`、`manifest_flush_seconds` 未被当前处理器读取，
已从默认配置删除。

## 10. 国家与单独发货（配置 + 代码常量）

- 国家目录：`processor-rust/src/country_catalog.rs`（别名表，非 JSON）。  
- 单独发货价区由 `pricing.single_shipment_price_marker_aliases` 标记。
- 单独发货匹配默认关闭；开启后按配置中心勾选的收件信息字段自动定位表头。
- 只有联合字段完整、只对应一个订单号且订单只有一个有效主要 SKU 时使用单独发货价；其余回退通用价格。
- 核价表单独发货子索引没有对应国家 + SKU 时才回退通用价格；如果 SKU 已存在但
  数量档位缺失、价格不可用或键重复，则保留该明确异常，不绕过错误改查通用价格。

---

## 11. 热更新语义

| 操作 | 是否读最新配置 |
|---|---|
| 已启动的 analyze/run 任务 | 否（任务开始时已 load） |
| 下一次 analyze / validate / run | 是 |

改别名或阈值后保存 JSON，再触发分析/试算即可验证。

## 12. 校验建议

```powershell
Get-Content -Raw -Encoding UTF8 config\extract_rules.json | ConvertFrom-Json | Out-Null
```

改正则后务必跑：

```powershell
pnpm run test:processor
```

修改配置结构、默认值或主进程校验时，还必须同步检查：

1. `resources/defaults/extract_rules.json`
2. `config/extract_rules.json`
3. `processor-rust/src/config.rs` 的配置测试
4. `src/main/index.ts` 的 `validateConfigContent`
5. 本文档中对应字段
