# 处理流程与匹配规则

本文档描述 **当前代码** 中的核价流程与匹配语义，主要实现于：

- `processor-rust/src/pricing.rs`
- `processor-rust/src/config.rs` / `country_catalog.rs`
- `src/main/index.ts`（IPC）
- `src/renderer/src/App.tsx`、`excel-preview.tsx`、`mapping-editor.tsx`

---

## 1. 总体流程

```text
选择订单文件/目录
        │
        ▼
price-check-analyze  ──► 识别订单 Sheet + 核价 Sheet
        │                 生成字段映射与试算覆盖率
        ▼
自动化决策（eligible / needs_confirm / error）
        │
   ┌────┴────┐
   │         │
 自动       人工确认映射
   │         │  price-check-validate 重试算
   └────┬────┘
        ▼
price-check-run  ──► 匹配写回 + 输出结果工作簿
```

| 阶段 | 触发 | 结果 |
|---|---|---|
| 分析 | UI 提交文件 → `price-check-analyze` | 候选 Sheet、建议映射、试算行/覆盖率、自动化状态、预览写回行 |
| 试算 | 映射变更 → `price-check-validate` | 校验错误、覆盖率、`writebackRows` |
| 执行 | 用户确认/自动 → `price-check-run` | 结果 xlsx/xlsm、异常与映射说明 |

每次 analyze / validate / run 都会经 `configPath` **重新 `load_config`**，因此保存配置后影响下一次操作，不影响已在运行的任务。

## 2. 进程通信

Main 通过 `child_process.spawn` 启动 `auto-pricing-tool-processor.exe`，**一行一条 JSON**。

### 2.1 核价相关命令

| action | 说明 |
|---|---|
| `price-check-analyze` | `files` + `configPath` + 可选 `headerTemplates` |
| `price-check-validate` | `file`/`files` + `mapping` + `configPath` |
| `price-check-run` | 文件列表 + 每文件 `mapping` / `writebackRows` / `cellEdits` 等 |
| `pause` / `resume` / `stop` / `shutdown` | 运行控制 |

### 2.2 典型事件

`ready`、`state`、`log`、`error`，以及核价进度/完成类事件（含分析报告、执行报告）。UI 通过 preload 暴露的 API 订阅。

## 3. 字段映射

### 3.1 映射完整性（前后端一致意图）

**订单侧必需：**

- 业务订单号列
- 国家三要素至少一列：二字码 / 英文 / 中文（受 `pricing.country_identity` 启用项影响读入）
- 至少一组 SKU 三元组：`qtyColumn`、`skuColumn`、`mergedQtyColumn` 均 > 0，且满足顺序约束
- 订单与核价不能是同一 Sheet

**核价侧必需：**

- SKU 列、国家列
- 至少一个数量档位列（`quantity_tier_columns`，含数量与列号）

### 3.2 SKU 三元组顺序

规则（`validate_price_mapping` / UI `mappingIsComplete`）：

1. 三列互不相同  
2. **从左到右**：原始数量列 < SKU 列 < 合并数量列  
3. **不要求相邻**（中间可有其他列）

示例：数量在 K、SKU 在 M、合并数量在 N → 合法。  
数量在 M、SKU 在 K → 非法。

### 3.3 空表头

- 映射下拉对空字符串表头展示为 **「空表头」**，可选。  
- 试算时：数量列可以是配置识别到的数量别名列，**也可以是空表头列**（人工指定）。

### 3.4 已移除：物流方式字段

订单/核价映射 **不再** 包含物流方式列；配置中亦无 `match_by_shipping_method`。历史「国家-物流」拆分逻辑已删除。

### 3.5 映射 UI 分组

字段编辑按订单 / 核价分组；物流相关入口已去掉。改列后约 500ms 自动 validate，也可手动「重新试算」。

## 4. 国家识别

### 4.1 整格匹配（核心变更）

国家单元格 **整段** 参与标准化，**不会**再执行类似：

```text
UNITED STATES-hold  →  错误地拆成  US + hold
```

实现注释与测试约定：`UNITED STATES-hold` 若不在国家目录别名中，则 **无法解析为 US**，核价行不进索引；订单侧同样无法把该字符串当成美国。

正式英文名 `UNITED STATES`、二字码 `US`、中文别名等仍可通过 `country_catalog` 解析为同一 ISO2。

### 4.2 标准化流程

1. 对输入做 `country_token`（去空白与部分标点后大写）。  
2. 在 `COUNTRY_ALIASES` 中匹配：ISO2 / 英文 / 中文 / 别名。  
3. 若整格为两位 ASCII 字母，可直接升为 ISO2（即使不在目录，也会留下 code）。  
4. 订单可同时提供 code/en/cn：  
   - 仅使用 `pricing.country_identity` 中启用的身份字段；  
   - 多字段解析出 **多个不同 ISO2** → `conflict = true`，**不静默挑一个**。  

核价表国家列：对单元格调用 `normalize_country_fields(raw, "", "")`，code 为空则该行不入价格索引。

### 4.3 与「二字码 > 英文 > 中文级联」的关系

当前实现是 **多字段分别解析后统一到同一 code（冲突则失败）**，并受 `country_identity` 开关过滤输入；**不是**「先只比 iso2，失败再比英文，再比中文」的严格阶梯优先级产品规则。若业务要强制定级联顺序，需另开需求改代码。

## 5. 价格索引与查找

### 5.1 键

```text
full_key   = country_iso2  +  SKU  +  quantity
prefix_key = country_iso2  +  SKU
```

**不包含** 物流方式或其他后缀。

### 5.2 建索引 `build_price_index`

- 从核价表头行（及数量档位表头行）之后逐行读取。  
- 每行：标准化 SKU、整格国家 → code；对每个 `quantity_tier_columns` 写入一条价格。  
- 若表中出现「单独发货」标记行（`single_shipment_price_marker_aliases` 规范化相等），**该标记行之后** 的数据进入 `single_shipment` 子索引。

### 5.3 查找 `lookup`

1. 国家或 SKU 空 → `SKU或国家缺失`  
2. 精确键命中：  
   - 多条不同价格 → `核价键重复`（**不静默选价**）  
   - 单条且可解析数字 → `matched`  
   - 单元格不可用 → `价格不可用`  
3. 未命中：  
   - 若 prefix（国家+SKU）存在 → `数量无对应档位`  
   - 否则 → `SKU或国家无法匹配`  

**注意：** 配置 JSON 中可能仍有 `quantity_policy: "nearest"` 等字段，但 **当前 `PricingRules` 与 `lookup` 不做就近档位**；必须数量档位精确匹配。

### 5.4 单独发货偏好 `lookup_with_single_shipment_preference`

- `pricing.single_shipment_matching_enabled` 默认关闭；关闭时所有订单使用标准/通用价格索引。
- 开启后，配置中心勾选至少两个联合字段（收件人姓名、电话、邮编、完整地址、邮箱）。
- 只有联合字段全部存在且有值、联合值只对应一个订单号、该订单只有一个数量大于 0 的有效主要 SKU 时，才判定为单独发货。
- 同订单多主要 SKU、字段缺失、联合值冲突或同一联合值对应多个订单号时，均使用标准/通用价格。
- 订单判定为单独发货，且存在单独发货子索引时：先查子索引。
- 若子索引结果不是「SKU或国家无法匹配」，直接采用（含数量无档位/重复等）。  
- 否则回退标准价表。

## 6. 订单行读取与聚合

### 6.1 读取

- 跳过无订单号行。  
- 使用 **最高优先级** SKU 组（`highest_priority_sku_qty_pair`：按 `merged_qty_column`、`sku_column` 取 max）。  
- SKU 空则跳过该行；数量无效/非整数记异常。  
- 国家 conflict 记异常。  
- SKU 支持 `normalize_sku_and_multiplier`（如带倍数写法）。

### 6.2 聚合键

按订单号 + 国家 code + 匹配 SKU + 是否单独发货 聚合数量，供查价使用。

---

## 7. 写回（writeback）

### 7.1 预览与执行

试算成功时生成 `writebackRows`（源行、是否匹配、核价、差额、数量、数量是否与合并数量不一致等）。执行时可带预览覆写与单元格编辑。

### 7.2 数量汇总规则

`build_writeback_rows`：

- 只使用最高优先级 SKU 组。  
- 按 **`(订单号, SKU)` 全局累加** 各行数量（× SKU 倍数），**不要求行相邻**。  
- 同一组只在首次出现的源行写入合计数量，同组后续行数量写 0。  
- `quantity_mismatch`：合并数量列与汇总数量是否一致。

UI「订单号重复 SKU」高亮可与写回不同：界面相邻重复高亮仅用于提示，写回逻辑始终按 (订单, SKU) 全局合并。

## 8. 自动化决策

`decide_automation` 综合：

| 条件 | 影响 |
|---|---|
| 无完整映射 / 订单与核价同 Sheet | 不可自动 |
| 试算行数 = 0 | error 类原因 |
| 行数 < `min_trial_rows` 且覆盖率 < 100% | 需确认 |
| 行数 ≥ `min_trial_rows` 且覆盖率 < `coverage_threshold` | 需确认 |
| 候选映射歧义（覆盖率差、分数差不足等） | 需确认 |
| `auto_run = false` | 关闭自动 |
| 以上皆通过 | `eligible` 可自动跑 |

覆盖率 = 匹配成功订单行 / 参与试算订单行。

---

## 9. 预览 UX 与未匹配定位

- 打开详情默认 **不全量** 加载表格（截断预览）。  
- 开启 **「未匹配定位」** 时：若尚未 `loadAll`，先加载订单+核价完整数据，再跳到未匹配行。  
- 已 `loadAll` 后再次开关定位 **不重复** 全量请求。  
- 支持表格内搜索（含 Ctrl+F）、行号点选、映射列着色（数量/SKU/合并数量同组配色）。

---

## 10. 输出

执行成功后生成结果工作簿（路径由输出目录与源文件名决定），并保留非订单 Sheet 结构相关能力（见导出实现）。订单侧需存在原始价格列方可生成结果文件。

异常类型包括但不限于：数量无效、国家冲突/无法识别、SKU 或国家无法匹配、数量无对应档位、核价键重复、价格不可用。

---

## 11. 明确的非行为（避免文档/旧记忆误导）

| 旧说法 | 当前代码 |
|---|---|
| 物流方式参与匹配 | **已删除** |
| `split_country_shipping` / 从国名拆 hold 等后缀 | **已删除** |
| `quantity_policy: nearest` 就近档位 | **未实现**（精确档位） |
| 映射必须数量/SKU/合并数量物理相邻 | **不需要**，只要左右顺序正确 |
| 写回仅合并相邻重复 SKU 行 | **否**，按 (订单号, SKU) 全局 |
