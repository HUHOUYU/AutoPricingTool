# 处理流程与匹配规则

本文档描述 **当前代码** 中的核价流程与匹配语义，主要实现于：

- `processor-rust/src/pricing.rs`
- `processor-rust/src/config.rs` / `country_catalog.rs`
- `src/main/index.ts`（IPC）
- `src/renderer/src/App.tsx`、`excel-preview.tsx`、`mapping-editor.tsx`

---

## 1. 总体流程

```text
选择订单文件/目录
        │
        ▼
price-check-analyze  ──► 识别订单 Sheet + 核价 Sheet
        │                 生成字段映射与试算覆盖率
        ▼
自动化决策（eligible / needs_confirm / error）
        │
   ┌────┴────┐
   │         │
 自动       人工确认映射
   │         │  price-check-validate 重试算
   └────┬────┘
        ▼
price-check-run  ──► 匹配写回 + 输出结果工作簿
```

| 阶段 | 触发 | 结果 |
|---|---|---|
| 分析 | UI 提交文件 → `price-check-analyze` | 候选 Sheet、建议映射、试算行/覆盖率、自动化状态、预览写回行 |
| 试算 | 映射变更 → `price-check-validate` | 校验错误、覆盖率、`writebackRows` |
| 执行 | 用户确认/自动 → `price-check-run` | 结果 xlsx/xlsm、异常与映射说明 |

每次 analyze / validate / run 都会经 `configPath` **重新 `load_config`**，因此保存配置后影响下一次操作，不影响已在运行的任务。

---

## 2. 进程通信

Main 通过 `child_process.spawn` 启动 `auto-pricing-tool-processor.exe`，**一行一条 JSON**。

### 2.1 核价相关命令

| action | 说明 |
|---|---|
| `price-check-analyze` | `files` + `configPath` + 可选 `headerTemplates` |
| `price-check-validate` | `file`/`files` + `mapping` + `configPath`；携带 `rowEdit` 时只重算指定行 |
| `price-check-run` | 文件列表 + 每文件 `mapping` / `writebackRows` / `cellEdits` 等 |
| `pause` / `resume` / `stop` / `shutdown` | 运行控制 |

### 2.2 典型事件

`ready`、`state`、`log`、`error`，以及核价进度/完成类事件（含分析报告、执行报告）。
整表试算返回 `price-validation`，绿色数量列的单行重算返回
`price-row-validation`，不会替换整表覆盖率和其他行。UI 通过 preload 暴露的 API 订阅。

## 3. 字段映射

### 3.1 映射完整性（前后端一致意图）

**订单侧必需：**

- 业务订单号列
- 国家三要素至少一列：二字码 / 英文 / 中文（受 `pricing.country_identity` 启用项影响读入）
- 至少一组 SKU 三元组：`qtyColumn`、`skuColumn`、`mergedQtyColumn` 均 > 0，且满足顺序约束
- 订单与核价不能是同一 Sheet

**核价侧必需：**

- SKU 列、国家列
- 至少一个数量档位列（`quantity_tier_columns`，含数量与列号）

### 3.2 SKU 映射组顺序

规则（`validate_price_mapping` / UI `mappingIsComplete`）：

1. 三列互不相同  
2. **从左到右**：原始数量列 < SKU 列 < 合并数量列  
3. **不要求相邻**（中间可有其他列）

示例：数量在 K、SKU 在 M、合并数量在 N → 合法。  
数量在 M、SKU 在 K → 非法。

这三个映射字段用于识别候选 SKU 组、显示预览和比较已有合并数量，不代表最终
数量一定直接读取该组的 `qtyColumn`。最终数量由第 6 节所述的
`quantity_source_columns` 和 `resolve_order_quantities` 计算。

### 3.3 空表头

- 映射下拉对空字符串表头展示为 **「空表头」**，可选。  
- 试算时：数量列可以是配置识别到的数量别名列，**也可以是空表头列**（人工指定）。

### 3.4 已移除：物流方式字段

订单/核价映射 **不再** 包含物流方式列；配置中亦无 `match_by_shipping_method`。历史「国家-物流」拆分逻辑已删除。

### 3.5 映射 UI 分组

字段编辑按订单 / 核价分组；物流相关入口已去掉。改列后约 500ms 自动 validate，也可手动「重新试算」。

## 4. 国家路由

### 4.1 核价表原值严格匹配

核价表国家列是价格路由的事实来源。路由键只去除首尾空格并统一大小写，
保留 `-`、`_` 等字符：

```text
FR-D ≠ FR ≠ FRD
```

订单按 `pricing.country_identity` 启用的顺序读取二字码、英文、中文原值，并依次查找
核价表中的相同原始路由。任一原始路由与完整 SKU 同时存在时，只在该路由中查数量档位。

不会执行 `FRANCE → FR`、`法国 → FR`、`FR-D → FR` 等标准国家转换后兜底。
所有原始国家值均找不到相同路由与 SKU 时直接进入未匹配详情。

### 4.2 国家目录的保留用途

`country_catalog` 仍用于订单国家展示和三字段冲突检查，不再参与价格索引键或查价兜底：

- 多字段可识别为不同标准国家时仍判定 `国家三要素冲突`。
- 自定义路由（如 `FR-D`、`BE-D`）可以直接进入核价索引，不要求存在于国家目录。
- 原始国家值缺失时判定 `SKU或国家缺失`。

## 5. 价格索引与查找

### 5.1 键

```text
full_key   = raw_country_route  +  SKU  +  quantity
prefix_key = raw_country_route  +  SKU
```

路由值保留业务后缀，单独发货状态仍是独立维度。

### 5.2 建索引 `build_price_index`

- 从核价表头行（及数量档位表头行）之后逐行读取。  
- 每行：标准化 SKU、保留国家原始路由；对每个 `quantity_tier_columns` 写入一条价格。
- 若表中出现「单独发货」标记行（`single_shipment_price_marker_aliases` 规范化相等），**该标记行之后** 的数据进入 `single_shipment` 子索引。

### 5.3 查找 `lookup`

1. 国家原值或 SKU 空 → `SKU或国家缺失`
2. 精确键命中：  
   - 多条不同价格 → `核价键重复`（**不静默选价**）  
   - 单条且可解析数字 → `matched`  
   - 单元格不可用 → `价格不可用`  
3. 未命中：  
   - 国家路由不存在 → `国家路由不存在`
   - 国家路由存在但没有完整 SKU → `SKU不存在`
   - 路由与 SKU 存在但当前数量没有档位 → `数量档位不存在`

上述任一失败均直接进入未匹配详情，**不转换标准国家或尝试其他推断路由**。

**注意：** 配置 JSON 中可能仍有 `quantity_policy: "nearest"` 等字段，但 **当前 `PricingRules` 与 `lookup` 不做就近档位**；必须数量档位精确匹配。

### 5.4 单独发货偏好 `lookup_with_single_shipment_preference`

- `pricing.single_shipment_matching_enabled` 默认关闭；关闭时所有订单使用标准/通用价格索引。
- 开启后，配置中心勾选至少两个联合字段（收件人姓名、电话、邮编、完整地址、邮箱）。
- 只有联合字段全部存在且有值、联合值只对应一个订单号、该订单只有一个数量大于 0 的有效主要 SKU 时，才判定为单独发货。
- 同订单多主要 SKU、字段缺失、联合值冲突或同一联合值对应多个订单号时，均使用标准/通用价格。
- 订单判定为单独发货，且存在单独发货子索引时：先查子索引。
- 子索引存在相同原始路由与 SKU 时，只使用子索引；数量档位、重复或价格不可用均直接报错。
- 子索引不存在相同路由与 SKU 时，回到通用索引并执行同样的原始路由严格匹配。

## 6. 主要 SKU 与最终数量

### 6.1 参与条件与主要 SKU

- 订单号先执行去首尾空白和大写规范化。
- **订单号为空的行完全跳过**，不参与数量计算、吸收、核价聚合或新增三列写回；
  原表中的合计、说明和空白行因此不会被当成订单。
- 主要 SKU 取评分最高的 SKU 映射组；当前代码按
  `(merged_qty_column, sku_column)` 最大值选择。
- 主要 SKU 为空时，数量留空并记录 `主要 SKU 为空`。

### 6.2 前一 SKU 与合法数量列

`quantity_source_columns` 先收集配置和映射识别到的所有 SKU/数量列，再执行：

1. 前一 SKU = 主要 SKU 左侧最近的 SKU 列。
2. 优先在「前一 SKU 右侧、主要 SKU 左侧」开区间内取最近数量列。
3. 右侧区间没有数量时，向前一 SKU 左侧回退。
4. 向左查找遇到更早 SKU 即停止；向右查找以主要 SKU 为硬边界。
5. 两侧合法区间都没有数量时，数量留空并记录
   `前一个 SKU 两侧的限定区间内找不到对应数量列`。

因此数量列可以和前一 SKU 不相邻，但**不能跨越任何 SKU 列**。

Daryll 回归例：前一 SKU 为 `FL2600814*5`，主要 SKU 为 `FL2600814`，
主要 SKU 右侧虽然还有数量 `99`，但不能跨过主要 SKU 读取；应回退读取前一 SKU
左侧合法区间内的数量 `1`，最终数量为 `1 × 5 = 5`。

### 6.3 SKU 表达式与数量换算

`parse_sku_expression` 先去除空白并转大写，再用 `+` 拆组件，并把每个组件末尾的
`*N` 解析为正整数倍数。`calculate_related_quantity` 按以下顺序处理：

| 关系 | 计算 |
|---|---|
| 主要 SKU 与前一 SKU 规范化后完全相同 | 直接使用合法数量列的数量；SKU 自身的 `*N` 不重复乘入 |
| 主要 SKU 是不含 `+`/`*` 的单一基础 SKU | 累加前一 SKU 中包含该基础串的组件倍数，再乘来源数量 |
| 双方为不同复合 SKU 且存在共同组件 | 按共同组件倍数比例换算；非整数结果向上取整 |
| 无共同组件、共同组件比例冲突、格式或倍数无效 | 数量留空，记录 `SKU关系无法计算` |

示例：

- `main=TC2501602`、`previous=TC2501602*3`、来源数量 `1` → `3`
- `main=TC2601361`、`previous=TC2601361-01+TC2601361-02`、来源数量 `1` → `2`
- `main=A*4+B`、`previous=A`、来源数量 `4` → `1`
- `main=A+B`、`previous=A*2+B` → 共同组件比例冲突，不猜测数量

### 6.4 同订单吸收

吸收严格按规范化订单号分组，不跨订单：

1. 只检查原 `TOTAL Price`/价格列明确等于 `0` 且数量已成功计算的行。
2. 独立 SKU 必须被同订单内另一条不同的复合主要 SKU 完整包含。
3. 只有一个可吸收目标时，该独立 SKU 行数量置 `0` 并从核价聚合排除。
4. 存在多个可吸收目标时不猜测，数量留空并记录
   `同订单内存在多个可吸收的复合主要 SKU`。

### 6.5 同订单同主要 SKU 合并与核价聚合

- 按 `(订单号, 完整主要 SKU)` 全局合并，不要求相邻。
- 首个保留行写合计数量，后续重复行写 `0`。
- 被吸收行不再进入该合并。
- 查价前再按「订单号 + 启用的国家原值序列 + 完整主要 SKU + 是否单独发货」聚合。
- 最终合计数量同时用于精确数量档位查价和新增 `数量` 列。

## 7. 写回（writeback）

### 7.1 预览与执行

试算成功时生成 `writebackRows`（源行、核价、差额、数量、数量错误以及可选的
SKU 问题列位上下文等）。执行时重新计算数量和价格；详情预览对新增三列的人工
覆写随后按源行覆盖计算结果。处理器仍兼容 `cellEdits` 输入，但当前详情 UI 不提供
订单源单元格编辑入口。

### 7.2 新增三列与金额

三列插入在订单侧映射的 `TOTAL Price`/原始价格列之后：

| 列 | 计算 |
|---|---|
| `核价[财务]` | 精确档位匹配价格；同一聚合组的价格只在首个源行保留，后续行写 0 |
| `金额差` | `核价[财务] - 原 TOTAL Price` |
| `数量` | 第 6 节最终数量；无法计算时保持空白，不伪装成 0 |

如果订单表头中存在规范化后等于 `EU TAX` 的列：

- 每个聚合组的 `核价[财务]` 总额 = 匹配价格 + 该组所有源行 EU TAX 之和。
- 写回时，各源行税额保留在各自行；组价格仍只放在首行。
- 金额差使用含税后的核价金额计算。
- 没有该列、单元格为空或不是数字时，税额按 `0`。

绝对值小于 `1e-9` 的金额差规范化为 `0`，避免浮点尾差。

### 7.3 详情预览可编辑范围

详情预览中只有绿色的三列可以双击编辑：

- 编辑 `核价[财务]`：只更新当前行，并按 `新核价 - 原 TOTAL Price` 联动金额差。
- 编辑 `金额差`：只更新当前行，并按 `原 TOTAL Price + 新金额差` 联动核价。
- 编辑 `数量`：发送带 `sourceRow` 的单行核价请求，只重新查询该行，并返回该行
  `核价[财务]`、`金额差`、`数量` 三个值；查价时仍包含该行 `EU TAX`。

数量单行重算不会触发整表 `price-validation`，不会重算其他行，也不会更新整表
覆盖率。查价失败时保留用户输入的数量、当前行核价与金额差置空，并提示具体原因。
订单源列、合计行、表头和其他普通列均不可通过当前详情编辑入口修改。

### 7.4 合计行复用

`pricing_writer::existing_total_row` 与预览 `existingWritebackTotalRow` 使用相同意图：

1. 只在最后一个订单写回行之后查找订单号为空、但行内存在内容的原有行。
2. 优先取包含 `Total`、`合计` 或 `总计` 的最后一个候选行。
3. 没有标签时，回退到最后一个候选非空行。
4. 没有候选行时，不写三列合计，**不会新建合计行**。

合计只汇总新增三列；原工作表的原有合计值与结构保持不变。预览数据被截断时不
猜测合计行，加载完整数据后才显示。

UI「订单号重复 SKU」高亮只用于提示；最终写回始终按同订单同主要 SKU 全局合并。

## 8. 自动化决策

`decide_automation` 综合：

| 条件 | 影响 |
|---|---|
| 无完整映射 / 订单与核价同 Sheet | 不可自动 |
| 试算行数 = 0 | error 类原因 |
| 行数 < `min_trial_rows` 且覆盖率 < 100% | 需确认 |
| 行数 ≥ `min_trial_rows` 且覆盖率 < `coverage_threshold` | 需确认 |
| 候选映射歧义（覆盖率差、分数差不足等） | 需确认 |
| `auto_run = false` | 关闭自动 |
| 以上皆通过 | `eligible` 可自动跑 |

覆盖率 = 匹配成功订单行 / 参与试算订单行。

## 9. 预览 UX 与未匹配定位

- 打开详情默认 **不全量** 加载表格（截断预览）。  
- 开启 **「未匹配定位」** 时：若尚未 `loadAll`，先加载订单+核价完整数据，再跳到未匹配行。  
- 已 `loadAll` 后再次开关定位 **不重复** 全量请求。  
- 支持表格内搜索（含 Ctrl+F）、行号点选、映射列着色（数量/SKU/合并数量同组配色）。
- 数量无法计算时，右侧状态卡只显示摘要和「详情」按钮；具体源行与错误原因在
  独立模态框中展示，不在窄侧栏内联展开。若错误来自前一 SKU 与主要 SKU 的关系，
  弹窗使用固定四列表格展示源行、两个 SKU 和问题原因，次要 SKU 使用橙色文字，
  主要 SKU 使用蓝色文字；SKU 单元格只显示 `列位 · SKU 值`，不显示角色名称。
  表头固定、表体独立滚动，约 100 条问题直接渲染，不分页。

## 10. 输出

执行成功后把结果工作簿直接写入用户选择的输出目录，文件名由源文件名安全化得到。
源文件不修改；如果结果文件已存在，写入器通过同目录临时文件和备份文件完成替换。

原表写回仅支持 `.xlsx` 和 `.xlsm`。`.xls`、`.xlsb` 虽可出现在扫描支持范围内，
但执行核价写回会明确要求先另存为 `.xlsx`，不会伪装成功。订单侧还必须存在
`TOTAL Price`/原始价格列，否则不生成结果文件。

新增三列只插入订单 Sheet；其他 Sheet 会移除对应插入列以维持原有结构和公式引用。

异常类型包括但不限于：数量无效、国家冲突、国家路由不存在、SKU 不存在、数量档位不存在、核价键重复、价格不可用。

## 11. 明确的非行为（避免文档/旧记忆误导）

| 旧说法 | 当前代码 |
|---|---|
| 物流方式参与匹配 | **已删除** |
| `split_country_shipping` / 从国名拆 hold 等后缀 | **已删除** |
| 查价前把 `FRANCE/法国/FR-D` 统一为 `FR` | **禁止**，核价表国家原值严格匹配 |
| `quantity_policy: nearest` 就近档位 | **未实现**（精确档位） |
| 最终数量直接读取评分最高组的 `qtyColumn` | **否**，按前一 SKU 限定区间动态选择数量列并换算 |
| 数量查找可以越过另一 SKU | **禁止**，左右两个方向都以 SKU 为硬边界 |
| 无订单号的合计行参与计算 | **否**，完全跳过 |
| SKU 吸收可跨订单 | **禁止**，吸收和合并均按规范化订单号隔离 |
| 映射组的数量/SKU/合并数量必须物理相邻 | **不需要**，映射组只要求左右顺序；最终数量另按 SKU 边界计算 |
| 写回仅合并相邻重复 SKU 行 | **否**，按 (订单号, SKU) 全局 |
| 程序总会新增一行写合计 | **否**，只复用原有候选合计行 |
| `EU TAX` 只参与展示 | **否**，会加入核价金额并参与金额差 |

- `exact_country_route_wins_without_standard_country_fallback`
- `existing_country_route_does_not_fallback_on_sku_or_tier_failure`
